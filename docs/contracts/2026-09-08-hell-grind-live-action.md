# Hell Grind: automatic, scoped live-action knowledge

## User request and scope
Analyze the public Hell Grind project and make its useful lessons automatic for
future photoreal stills and live-action video requests. This is a synchronous
research/skill-maintenance task, not production and not an additional team.

## Acceptance
- Inspect the public brief, CINEDANCE, ACTING and LIRA attachments. Separate
  observed source claims from our adaptation and untested quality hypotheses.
- Reuse the existing live-action wiki profile and existing Seedance adapter;
  do not install competing external skills or copy provider/approval procedures.
- Route photoreal image requests from image-prompt and live-action planning from
  videodirector; existing v4 knowledge selection must retain the full compact
  live-action profile within its 2,400-character entry budget.
- Still-only requests do not acquire dialogue, timecodes, forced triptychs or
  ten-shot stress testing. Multi-shot identity remains governed by its owner.
- Exclude mandatory horror styling, blanket wide openings, age/filter evasion,
  provider switching, arbitrary retries and hardcoded timings.
- Verify positive and negative knowledge routes, prompt compiler examples,
  deployment parity for changed files, and source preservation.
- Preserve the active monitoring contract/top-level harness fields. Record this
  independent closeout under recentCloseouts. Commit/push only this change.

## Deployment boundary
Deploy only videodirector through the one-skill deployer. Apply the reviewed
image-prompt routing-only patch with a dry run and an archived original; the
third-party compiler remains otherwise unchanged. Wiki is the knowledge owner;
wiki-extract is its version-controlled release snapshot. Do not deploy pending
Seedance/runtime executable changes or touch projects, queues, media or schedules.
