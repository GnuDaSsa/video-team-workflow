# 성남3D식품프린팅 — 컷 설계 예시와 로딩 예제

저작 교육용 설계 예시다. 실제 제출 프롬프트·Astra seal·생성 승인·의료 적합성 판정이 아니다. 15초는 현재 source lock이며 사용 컷의 최종 편집 길이와 다르다. 한 컷에서 지도→도시→연구→식사를 모두 수행하지 않는다.

|---|---|---|---|---|
| C01 한반도 | 성남 위치 소개 / 검증된 지도 / 위치로 접근 | 한반도와 성남 위치 관계, 라벨은 후반 | 넓은 지형→완만한 접근→성남 주변 구도 | 북쪽 방향·지도 형태 유지, 다음 컷 중심점 일치 |
| C02 첨단도시 진입 | 미래 기술도시 규모 / 설계 도시 / 진입 | 전경 연결교·중경 거리·후경 고층군, 현실 지리 기록 아님 | 거리 입구→단일 전진→광장 진입 | 건물 topology·창 방향 유지, C03 이동 방향 연결 |
| C03 상승 | 도시 속 계획센터의 맥락 / 도시 / 상승 | 광장 아래·도시 위, 중광각과 깊은 공간 | 광장→부드러운 상승→센터 방향이 읽히는 조망 | 상승 속도와 빛 유지, 과도한 orbit 추가 금지 |

## C07 설계 카드 상세
- 목적: 식품이 노즐의 연속 압출과 적층으로 형태를 얻는 과정을 이해시킨다.
- 주인공: 한 개의 식품 압출 노즐과 바로 아래 적층면. 연구원 손은 핵심이 아니므로 프레임 밖.
- 행동: 접촉을 유지하며 단일 층을 쌓는다. 한 컷에 원료 투입·출력·식사를 겹치지 않는다.
- 구도: 좌하단 적층면, 중앙 접촉부, 흐린 후경 장치. 접촉점이 가리지 않게 한다.
- 렌즈: 측면 근접 macro 느낌, 노즐 끝과 현재 층의 접촉이 동시에 읽히는 심도.
- 카메라: 고정 또는 미세 전진 중 하나를 실제 컷 목적에 따라 선택. 노즐 이동과 카메라 이동을 별도로 기록.
- 빛/재질: 측면 확산광, 식품 페이스트의 점성·부드러운 표면, 장치 금속의 절제된 반사.
- 고정: 노즐 수·지름·장치 구조·재료색·층 위치. 이미지에는 접촉 중인 한 순간, 영상에는 15초 안의 시작→한 층 쌓기→안정 종료를 저작.
- 참조: REF_MACHINE=공간/장치 형태, REF_FOOD=재질/색, 선택적인 PREVIS=카메라/동작 의도. 실제 파일이 없으면 해당 토큰을 넣지 않는다. 시트 배경·레이아웃 제외.
- 실패 수정 예: ‘6–8초 노즐이 떠서 재료가 공중에서 생성됨’ → 접촉/행동 항목만 ‘접촉한 압출 재료가 기존 층 위로 연속 연결됨’으로 구체화. 카메라·색·장치는 유지. 수정 결과의 전 구간을 따로 확인한다.

## 기존 지원 경로로 로드
Aside context의 실제 session/model 필드는 session-context.mjs가 만든 값을 유지한다. 그 위에 다음 컷별 데이터를 합치고 기존 request→author-task를 사용한다. 아래는 완성 context가 아니라 추가할 필드의 예다.

```json
{"knowledge_tags":["reference","product","camera"],"knowledge_version":"chatgpt-web","user_instruction":"식품 노즐 적층 장치의 한 순간. 실제 승인 참조의 공간과 재질 역할을 분리하고 접촉점과 전중후경을 명시. 프로젝트 brief 및 overrides의 사실 제약과 No-I2V를 유지."}
```
영상 저작 시 stage=seedance_prompt, knowledge_version=seedance-2.0, tags=[reference,product,camera]를 사용하고 user_instruction에 시작/핵심행동/종료·속도·고정요소와 인접 컷 연결을 넣는다. core/reference/physics/camera가 선택된다. 무관한 text/audio/identity 태그를 모두 넣지 않는다. 실제 이미지/영상 결과 QA는 별도다.

Codex는 기존 프로젝트 planner/video_attributes.json의 global.methods에 advanced_prompting을 병합해 두었다. 다음 `video-codex-runtime knowledge-select --project <실제 프로젝트> --block <실제 블록 ID>`가 해당 카드를 선택한다. 선택 결과는 새 저작용이며 옛 인수증을 갱신하지 않는다. 이 예시 C01–C12는 교육 ID이므로 실제 실행맵 ID로 대체한다.

## 대기 중 작업 기록 예시
컷 ID | 이미지/참조 승인 path/hash | prompt hash | Runway job ID(미확인 시 빈 값) | 제출 상태 | 마지막 확인 | 다음 확인(+20분) | 독립 준비할 다음 컷.
접수 불확실 상태는 SUBMISSION_UNCERTAIN으로 기록하고 동일 Generate를 재클릭하지 않는다. 이 표는 운영 지침이며 자동 polling/병렬 제출 기능이 아니다.

## 이번 프로젝트의 확정 길이 — 모든 장면 15초 생성
최신 사용자 지시: “노노 모든 장면은 15초로 생성하셈”. C01–C12를 포함한 모든 실제 영상 장면은 예외 없이 source_duration=15초다. 도시·센터·상담·식사·장비 디테일 모두 동일하며, 이전 8초 및 12~15초 생성 후보는 폐기한다. 필요한 짧은 길이는 최종 편집에서만 자른다. 각 컷에 source_duration=15 / edit_in / edit_out / 앞 handle / 뒤 handle을 별도 기록하고, 시작 진입과 끝 반응의 여유를 확보한다. 기존 15초 lock과 새 프롬프트 시간 구조·실제 UI·결과 duration 검증을 일치시킨다.
