# 컷 작성에 적용하는 이미지·영상 프롬프팅

## 적용과 권위
이 문서는 사용자가 요청한 로컬 제작 지식 전수 원문이다. 창작 방법이며 실행 엔진·승인 정책·품질 보증이 아니다. 기존 awesome-ai-motion 선택 문법·고정 commit·카탈로그를 보존한다. 기존 프로젝트 승인 참조, 의료/사실 제약, 선택된 제작 모드가 예시보다 우선한다.

## 1. 한 컷의 설계 카드
다음 항목을 따로 작성한 뒤 서로 충돌하지 않는 문장으로 합친다.
- 목적: 관객이 이 컷 뒤에 이해할 한 가지.
- 주인공: 시선이 머물 대상 하나와 보조 대상의 역할.
- 행동: 관찰 가능한 핵심 변화 하나. 복합 동작은 그 변화의 원인·접촉·반응으로 연결한다.
- 구도: 전경/중경/후경, 화면 좌우, 크기, 여백, 대상 간 거리와 가림 관계.
- 렌즈: 필요한 화각·거리·원근·심도. 렌즈 숫자가 물리 시뮬레이션을 보장하지 않는다.
- 카메라: 시작 위치→주 경로→종료 위치, 속도·가감속. 피사체 동선과 분리.
- 조명: 실제 광원 방향, 색온도, 그림자와 인접 컷의 연결.
- 재질: 표면 거칠기·반사·두께·유연성 등 장면에서 보이는 속성.
- 고정요소: 얼굴·옷·건축·물체 수·색·위치 중 변하면 안 되는 항목.
- 실패 기준: 정체성 변화·접촉 이탈·재질 떨림 등 실제로 관찰 가능한 탈락 조건.
필수 인과·접촉을 설명하는 단서만 남기고 모든 항목을 숫자/좌표로 채우지 않는다. 간결한 목적·동작 진행·카메라 시작/변화/끝·연속성을 우선해 모델이 새 구도와 동선을 만들 여지를 둔다.

## 2. 이미지와 영상 분리
이미지는 한 순간의 공간 구조를 쓴다. 전후 시간의 사건을 한 화면에 섞거나 콜라주를 요구하지 않는다. 영상은 시작상태→하나의 핵심행동→종료상태, 진행 속도, 고정요소를 쓴다. 시작·끝 상태는 연출 설명이지 자동 Keyframe 업로드 지시가 아니다. No-I2V에서는 재사용 참조로 저작하고 per-cut start/end 이미지를 새로 만들지 않는다. 의도적으로 승인된 복합 카메라 동작은 의미를 보존하되 충돌하는 명령만 정리한다.

## 3. 참조 역할표
각 실제 첨부에 ID/path/hash, 역할(얼굴/옷/공간/스타일/카메라), 가져올 특징, 가져오지 않을 특징을 남긴다. 한 이미지가 여러 역할이면 영역별로 명시한다. 시트의 패널·격자·레이블·흰 배경은 장면에 복제하지 않는다. 얼굴 참조가 옷·포즈·빛까지 강제하는 것은 아니다. 참조 번호는 시간 순서가 아니다. 없는 참조 토큰을 만들지 않는다.
캐릭터 시트(정체성/의상), 빈 배경(환경), 소품·음식·장비(형태/재질)를 역할별로 분리하되 기존 승인 자산을 재사용한다. 다중 참조에서 새 구도와 동선을 저작하며 완성 장면 한 장을 자동으로 시작 프레임에 고정하지 않는다. 명시적으로 시작 프레임이 필요한 예외는 컷 ID·이유·승인 근거·모드를 따로 기록한다. Seedance Reference와 Keyframe은 구별하며 모드 전환 권한을 추론하지 않는다.

## 4. 앞뒤 컷 연결
컷 작성 전에 이전 종료/현재 시작/현재 종료/다음 시작의 시선, 화면 이동 방향, 동작 단계, 색, 광원 방향, 물체 위치를 비교한다. 축을 넘거나 방향을 뒤집으면 의도와 연결 샷을 기입한다. 컷마다 멋진 카메라를 추가하기보다 하나의 관객 동선을 유지한다. 실제 지도·위치는 검증된 바탕과 후반 라벨을 사용하고, 설계된 미래도시는 현존 촬영 기록으로 주장하지 않는다.
실제 제품·장소 에셋 생성 전에 제조사·기관·운영자 등 일차 출처의 URL/확인일/뒷받침하는 사실을 기록한다. 실제 외형·운영 사실과 개념/미래 응용 장면을 구분한다. 한 프로젝트의 인물 캐스팅·미감·길이·리듬·차원 전환은 다른 프로젝트에 자동 강제하지 않는다.

## 5. 관찰 기반 수정
관찰한 실패를 시간·영역·현상으로 좁힌다(예: 6초부터 노즐과 적층면이 떨어짐). 원인 가설 하나와 수정 필드 하나를 선택하고 나머지 고정요소는 보존한다. 매회 형용사를 더하거나 전체 프롬프트를 다시 쓰지 않는다. 수정 전/후 문구와 결과 경로를 기록한다. knowledge selection/hash/저작 반영 기록은 지식 전달 증거다. 생성 이미지 실물 검수, 영상 전 구간 재생·필요한 청취와 사실 검토는 별도이며, 지식 패킷 PASS가 결과 PASS가 아니다.

## 6. Blender 프리비즈
Blender는 카메라 이동·블로킹·속도·접촉 의도를 설명하는 참조다. 움직임만 사용할 때 proxy 외형·색·그리드는 제외하고 승인 이미지가 외관을 맡는다. 생성 결과의 좌표·거리·궤적 정확성을 보장하지 않는다. 실제 source restyle 요청과 motion-only 참조를 구분한다.

## 7. 대기 시간 활용
이미지/참조가 승인되어 준비된 컷부터 현재 승인 모드로 영상화한다. 그 대기 시간에 독립적인 다음 이미지·기획을 준비한다. 단일 Runway composer 소유자를 유지하고 두 번째 제출 루프·새 자동화 엔진을 만들지 않는다. 각 제출의 컷/프롬프트 해시/provider 작업 ID/상태/확인시각을 기록한다. 접수가 불확실하면 같은 제출을 반복하지 말고 기존 작업을 확인한다. 실제 계정/모드의 동시 작업 제한을 존중하고 정해진 slot 수를 추측하지 않는다. 기존 사용자 승인·프로젝트 HOLD·필수 참조 QA/게이트를 유지하고 준비된 적격 컷부터 진행한다. 원격 생성은 계속되어도 작성 화면은 한 owner만 조작하며 대기 중 독립적인 기획·에셋 개선·QA를 수행한다. 실행 간격·비용·불확실한 접수 대조는 단일 원본 `codex-skills/seedance-prompt-en/seedance-production.md`의 Continuation selection 및 Submission reconciliation and account cost evidence를 따른다. 프로젝트의 명시적 예외는 overrides를 먼저 읽는다. 문서 반영만으로 실제 예약이 등록/실행됐다고 주장하지 않는다.

## 선택·적용 기록
Aside: 기존 context.knowledge_tags로 reference, camera, action/product, edit 등을 필요한 것만 선택한다. request가 만든 author-task 본문을 실제 저작자에게 전달한다. image/video core는 자동 선택된다. 컷 설계와 인접 컷 연결, 선택 카드 ID→반영 문구를 brief 또는 기존 저작 노트에 짧게 남긴다. 이를 별도의 품질 인증으로 쓰지 않는다. 과도한 태그로 6개/9,000자를 넘기면 컷의 실제 목적을 좁히고 재요청한다.
Codex: planner/video_attributes.json의 해당 block methods에 advanced_prompting을 기존 값과 함께 넣고 기존 knowledge-select를 사용한다. 패킷에서 advanced-shot-contract가 실제 선택됐는지 확인한다. 이미지 작성은 videodirector의 이 문서 포인터에서 필요한 항목만 읽는다. 기존 패킷·인수증은 소급 수정하지 않고 새 저작만 새 패킷으로 수행한다.
