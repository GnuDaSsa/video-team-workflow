# 웹 ChatGPT Images 2.5 생성·편집과 인물 캐스팅

## 기본 경로

Aside 영상팀의 모든 이미지 생성/편집은 웹 ChatGPT Images 2.5가 기본이다. Astra는 문구만 작성하고 현재 세션 모델이 웹 실행·다운로드·QC를 맡는다. 웹 접근 실패를 내장 imagegen/API로 자동 대체하지 않는다. 제품·풍경·스타일프레임에도 아래 웹 조작/증거 절차를 적용한다.

인물이 AI 모델/광고 헤드샷처럼 정형화됐다고 거절되면 아래 인물 캐스팅부터 다시 해결한다. 거절된 시트를 identity reference로 재활용해 표면 질감만 더하지 않는다. 해당 인물의 영상 제출은 HOLD한다.

## 확인된 제품 사실

- OpenAI의 2026-09-08 발표는 ChatGPT Images 2.5를 web/desktop/mobile의 ChatGPT에 제공한다고 설명한다.
- Flare와 Sunburst는 공식 API 모델명이다. 문서상 Flare는 속도, Sunburst는 demanding quality를 우선하는 선택이다. **웹 UI에서 두 모델을 직접 고르는 기능은 별도로 확인해야 한다.** 채팅의 추론 강도 또는 prompt에 적은 `Sunburst/max`를 이미지 backend 선택 증거로 쓰지 않는다.
- 공식 가이드는 실제 사진을 원하면 photographic medium, 구체적인 시각적 사실, 자연스러운 조명/재질/구도, 편집할 것과 보존할 것의 분리, 한 번에 하나의 수정, 이전 결과를 실제 편집 입력으로 재사용할 것을 권장한다. 수정 누적에도 원하지 않는 변화가 생길 수 있어 매번 검사해야 한다.
- 웹에서 이미지에 직접 comment로 국소 편집하는 제품 기능이 발표됐다. 실제 계정의 UI에서 노출됐는지 확인한 뒤 사용한다.

출처:
- https://openai.com/index/introducing-chatgpt-images-2-5/
- https://developers.openai.com/api/docs/guides/image-prompting

위 문서는 모델의 일반 성능 설명이다. 특정 인물의 자연스러움 개선이나 웹이 Aside 내장 생성보다 우월하다는 실험 증거가 아니다.

## 인물 먼저, 시트는 나중

1. **캐스팅 카드:** 성인 나이대, 실제 활동/직업, 체형, 기억나는 얼굴 구조 2~3개, 자주 짓는 미세한 표정, 머리 손질 상태. 국적만으로 고정관념을 만들지 않는다.
2. **단독 얼굴 후보:** 가슴 위 또는 head-and-shoulders 한 장, 눈높이, 눈/귀/턱이 판독되는 거리. 자연스러운 단일 창빛 또는 단순한 중성광. 처음부터 3분할·전후면·패션 완성도를 한꺼번에 요구하지 않는다.
3. **캐스팅 선택/QC:** 작게 봐도 기억나는 인상인지, 눈/입/피부가 살아 있는지, 전형적인 미용 광고 얼굴인지, 비대칭이 자연스러운지 평가한다. 사용자 거절은 자동 점수보다 우선한다.
4. **identity master:** 선택된 원본을 다운로드하고 경로/hash/웹 대화 URL을 보존한다. 이후 다른 인물을 텍스트로 재추첨하지 말고 이 이미지를 실제 입력으로 쓴다.
5. **몸·의상:** 얼굴 구조/나이/눈 간격/코끝/입/헤어를 보존하면서 전신과 의상만 추가한다. 그 다음 후면을 파생한다. 한 번에 하나의 변경으로 identity drift를 찾기 쉽게 만든다.
6. **캐릭터 시트:** 승인 face master와 body/back 결과를 근거로 필요한 triptych를 만든다. 생산용 정면 body/후면 body/큰 3/4 face 역할을 유지하고, 얼굴이 변하면 파생 결과를 거절한다. 3분할 자체가 캐스팅을 대신하지 않는다.
7. **No-I2V 연결:** 시트/최소 crop을 인물 reference로 실제 첨부하고 패널별 역할을 prompt에 명시한다. 장면 구도·동작·카메라·조명은 영상 prompt가 소유한다. 시트를 첫 프레임으로 재생하지 않는다.

## 프롬프트 가설과 피할 것

실제 결과로 검증할 가설이지 만능 공식이 아니다.

- `완벽한 미남 + 또렷한 턱선 + 운동선수 + 고급 화보 + 완벽한 피부`를 동시에 요구하면 정형화된 미형으로 수렴할 위험이 있다. 구체적인 캐스팅 선택과 작은 반응을 우선한다.
- 개성은 상처/주근깨/모공/땀을 덧칠하는 것이 아니다. 얼굴 비례, 시선, 입의 습관, 생활 맥락에서 만든다. 결점을 희화화하거나 지저분함으로 치환하지 않는다.
- 피부는 실제 촬영 거리에서 읽힐 정도만 묘사한다. `ultra-detailed pores`, 과도한 sharpening/HDR, 모든 부위의 거친 texture를 피한다.
- 얼굴 선택 단계에서 cinematic grade, fashion retouch, teal/orange, heavy rim/volumetric light를 빼서 identity 자체를 판단한다. 영상의 화려한 조명은 나중에 적용한다.
- `real photograph`, 촬영 상황과 피사체의 관찰 가능한 반응을 구체적으로 쓴다. 장비명은 보장값이 아니라 appearance cue다.
- 필요하면 공냥 prompt의 긍정형 구조를 쓰되, 이 웹 2.5 분기는 공식 가이드가 허용하는 짧은 보존/제외 제약을 사용할 수 있다. 이미지2용 오래된 분량/파라미터를 웹 2.5에 그대로 강제하지 않는다.

## 웹 조작

**입력 전 필수:** `author-executor.md`의 actual author 흐름으로 `image_prompt`를 실제 Astra에 맡기고 `seal → submission.mjs prepare/verify`를 완료한다. 현재 세션이 Astra가 아니면 실행자가 생성/편집 문구를 직접 쓰지 않는다. `Astra/R4` 자산 참조는 모델 호출이 아니며 `imagegen.generate`는 웹 ChatGPT가 아니다. 검증 payload 없이 composer 입력/생성을 시작하지 않는다.

1. 관련 ChatGPT 탭이 있으면 attach한다. 없으면 https://chatgpt.com/ 을 연다. fresh snapshot으로 계정과 composer를 확인한다.
2. `파일 등 추가 → 이미지 만들기`가 있으면 선택하거나 명시적으로 이미지 생성을 요청한다. 이미지 template가 있더라도 polished Headshot preset을 자동 선택하지 않는다.
3. 검증된 payload JSON의 `prompt`를 파일에서 읽어 관측된 composer locator로 그대로 입력한다. 실행 중 새 prompt 문자열을 구성하지 않는다. `.fill`이 contenteditable 값 불일치를 반환해도 바로 재입력하지 않는다. snapshot의 전체 텍스트를 원문과 비교한다. ChatGPT paragraph/blank-line 표현만 달라졌고 내용이 모두 같다면 한 번만 전송한다.
4. 진행률/생성 중 상태를 관측한다. preview를 최종 결과로 저장·승인하지 않고 완료 이미지가 나올 때까지 기다린다.
5. 결과를 다운로드해 원본 파일로 검수한다. 가급적 동일 인물 후보의 전신/시트는 같은 대화에서 이어 편집하되, 실제 이전 이미지가 reference로 사용되는지 확인한다. 기억에만 의존하지 않는다.
6. 새 입력/이미지 편집의 외부 전송은 사용자 요청 범위에서만 한다. 개인 사진은 필요한 승인/권리 범위를 확인한다. `requested_product=ChatGPT Images 2.5`와 실제 UI의 `observed_product`를 분리하고 backend variant가 미노출이면 `unverified`로 기록한다. 웹에서 2.5 표기가 보이지 않았다는 사실을 숨기지 않는다. UI가 명확히 다른 버전만 제공하면 요청한 2.5 사용 성공으로 처리하지 않는다.
7. `image_prompt` Astra 인수증을 검증한 원문만 입력한다. UI 제한 때문에 문구를 줄이거나 편집 지시를 추가해야 하면 Astra 프롬프팅으로 되돌린다. 웹 조작·이미지 QC·다운로드는 author child에 넘기지 않는다.

## 작은 비교 실험

- 1차: 같은 출력 형식·구도에서 캐스팅 서술만 바꿔 독립 후보를 비교한다.
- 2차: 선택 얼굴을 보존하고 의상만 변경한다. 얼굴 구조와 나이/헤어가 유지되는지 검사한다.
- 3차: 전신/후면 파생과 영상의 시트 첨부 일관성을 검사한다.
- web vs 다른 생성 경로를 비교하려면 동일 prompt/reference/출력크기 조건을 유지한다. 조건을 바꾼 한 장만 보고 모델 우위를 주장하지 않는다.
- 정확성/자연스러움/개성/identity 유지/시트 확장성/생성 시간은 별도로 기록한다. 사용자 최종 선택 전에는 `CASTING_CANDIDATE`이며 승인 캐릭터가 아니다.

## 실제 UI 실험에서 확인한 사항

- 웹 ChatGPT에서 `이미지 만들기`로 단독 실사 캐스팅 초상 1장을 생성하고, 그 이미지의 편집 화면에서 티셔츠 색만 바꾸는 1회 편집을 완료했다.
- 이미지 viewer에 마크업/댓글 달기/배경 제거/지우기/크기 조정/저장과 원본·편집본 전환 UI가 노출됐다. 도구 노출을 확인한 것이며 모든 기능을 실행 검증한 것은 아니다.
- 원본과 편집본 모두 실제 Save download event로 PNG를 받았고 1086×1448이었다. 이 해상도는 웹 결과의 관측값이지 API 지원 size 규칙이 아니다.
- 상단 55% 영역의 SSIM은 약 0.9527로, 지정하지 않은 영역도 pixel-identical하지 않았다. 이 수치는 얼굴 인식/identity 점수나 미감 점수가 아니다. 한 장의 편집만으로 장기 identity 보존을 보장하지 않는다.
- 단독 캐스팅→의상색 1개 수정의 웹 경로만 실증했다. 전신/후면/시트 확장, 영상 identity 유지, Flare와 Sunburst 또는 web과 Aside 내장 생성의 공정한 A/B 우위는 아직 검증하지 않았다.
- 이 실험 인물은 `CASTING_CANDIDATE`다. 사용자 승인을 받은 댄스 캐릭터라고 간주하지 않는다.
