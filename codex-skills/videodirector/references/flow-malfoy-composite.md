# Flow 요청 분기 — 말포이식 합성

## 목적과 적용

사용자가 FLOW/Flow/플로우로 **영상 생성을 요청하면** 이 제작 분기를 읽는다.
별도로 “말포이식”을 요구하거나 일반 Flow/합성형 중 하나를 다시 선택하게 하지 않는다.
질문·자료 분석·workflow라는 일반 단어는 제작 실행을 승인하지 않는다.
프로바이더 선택·공통 게이트·실행 범위는 runtime/AGENTS.md §1.4가 소유한다.

기본 해석은 **AI 연기 소재 + 분리된 코드 모션그래픽 + 음악 기준 합성**이다.
이는 말포이 캐릭터, 특정 게임 UI, 팔레트, 의상, 언어를 복제하라는 뜻이 아니다.
사용자가 clean footage만 요청하거나 후반 합성을 제외하면 그 범위를 우선한다.
공간과 인물의 상호작용이 필요한 컷은 full-scene 소재로 남긴다. 작품 수준의
합성 분기 안에서 컷 역할을 정하는 것이지, 별도 제작 모드를 다시 묻는 것이 아니다.

- 제작 시간·비용·GPU 성능·효과 수는 제작자 보고이며 우리 환경 실측이 아니다.

## 1. 합성부터 역산하는 소재 설계

1. 승인된 캐릭터 identity와 음악/내레이션 spine을 확보한다. 새 캐릭터 시트가
   필요한 경우 기존 identity gate를 따른다. 영상 요청만으로 음악 provider를 바꾸지 않는다.
2. 각 컷을 `keyed_character`, `full_scene`, `graphic_only`로 분류한다.
3. keyed_character는 캐릭터·의상·소품과 겹치지 않는 균일한 배경색, 머리/손/발의
   동작 여백, 일정한 조명으로 설계한다. 블루 #1E3CFF는 사례 값이지 의무가 아니다.
   공개 키어는 블루 전용이므로 다른 색에는 별도 조정·시험이 필요하다.
4. 승인된 source image를 실제 영상 입력에 연결한다. 단색 유지에는 첫 프레임,
   명확한 변신 목표에는 지원이 확인된 첫/끝 프레임, 공간 탐색에는 지원이 확인된
   참조 입력을 검토한다. 입력 방식별 성능은 우리 소스에서 짧게 비교한다.
5. 합성용 영상에는 인물의 행동·표정·머리·옷 움직임과 필요한 카메라만 맡긴다.
   한 소스 안의 임의 컷 분할과 불필요한 생성 자막/음악을 피한다. 정확한 타이포,
   비트 효과, 컷 도착 시점은 후반의 책임으로 분리한다.

## 2. 매팅과 시간축 QC

색차 키는 세부 윤곽, AI 분할은 인물 영역 보호/배경 제거의 보조 역할을 맡긴다.
애니 전용 마스크를 실사에 무조건 적용하지 않는다. 매팅 결과는 별도 파생 자산이며
원본 hash·source asset ID·방법/설정·알파 형식·검수 구간을 기록한다.

- 흰색/어두운색/고채도 배경에 각각 합성해 머리·손가락·망토·소품의 테두리를 본다.
- 정지 샘플뿐 아니라 전체 소스를 재생해 윤곽 깜빡임, 소실, 색 번짐을 확인한다.
- 인월드(full_scene) 장면을 억지로 누끼 처리하지 않는다.
- 워터마크 제거를 이 분기의 목표나 자동 단계로 넣지 않는다. 제공 조건을 확인한다.
- CapCut 전달 시 작은 알파 샘플을 먼저 왕복 시험한다. 기존 로컬 실험에서는
  VP9 WebM이 검게 합성된 적이 있고 ProRes 4444가 통과했으나, 현재 버전의 증거를
  대신하지 않는다. `/Users/gnudas/wiki/queries/mv-typography-capcut-remotion-tests-2026-09-22.md`
  는 기술 이력만 참고하며 사용자에게 반려된 미감을 재사용하지 않는다.

## 3. 공통 모션그래픽 지식

Flow 이외의 영상팀도 **코드 모션그래픽/키네틱 타이포/캐릭터 쇼케이스를 설계할 때**
이 절만 읽을 수 있다. 지식 재사용은 Flow 전환이나 모든 영상의 고밀도 효과 적용을 뜻하지 않는다.

### 레이어 계약

| 순서 | 책임 | 수정 단위 |
|---|---|---|
| BG | 패턴, 색면, UI 공간, 배경 타이포 | 팔레트/패턴/음악 cue |
| Subject | 승인된 캐릭터 연기 또는 full-scene | source ID/in-out/transform |
| FG | 이름판, 정확한 문구, 로고, 전경 가림 | 텍스트/조판/등장/읽기/퇴장 |
| Finish/audio | 제한된 화면 효과, 믹스, 동기 | 강도/프레임/라우드니스 |

캐릭터만/배경만/전경만/완성본을 같은 프레임에서 비교할 수 있게 만든다.
색상·문구 수정은 해당 레이어만, 연기 실패는 생성 소재만 되돌린다.
코드 기반 scale/pan은 2D 재구도이며 새로운 시점/가려진 신체를 생성하지 않는다.
전신 영상 확대가 얼굴 클로즈업 해상도를 자동 보장하지 않는다.

### 음악의 시간표

- 실제 승인 오디오의 phrase·drop·강세·쉼을 듣고 cue로 표시한다. BPM만으로
  모든 컷을 균등 분할하지 않는다. half/double BPM 오검출과 drift를 확인한다.
- 하나의 fps/timebase를 사용하고 `frame = round(time_sec * fps)`로 사건을 정렬한다.
  170 BPM/78컷/효과 278개는 목표치가 아니다.
- 각 사건에 **의도 → 시작 → 도착 → 읽기 유지 → 퇴장**을 기록한다.
  타이포는 도착 프레임뿐 아니라 실제 읽을 시간을 확보한다.
- 컷에는 source asset/hash, source in/out, target frames, BG/FG IDs, anchor,
  scale/pan, palette, cue ID, 효과 강도를 기록한다. 의상/구도 변화와 이야기 순서를
  먼저 결정하고 난수/자동 후보 선택은 그 제약 안에서만 쓴다.
- 픽셀 변화량의 peak는 동작 후보일 뿐이다. 얼굴 붕괴·카메라 흔들림도 높은 점수가
  나올 수 있어 실제 연기 검수로 선택한다. ASR 역시 발음/가창 미감 판정기가 아니다.

### 모션 모듈과 배치

소수 모듈을 목적에 따라 조합한다: reveal/card, nameplate slam, kinetic wall,
beat cut-in, clip wall, end stamp. 각 모듈은 색상·문구·폰트·레이아웃·cue·강도를
매개변수로 분리한다. 모듈 목록은 구현 완료 목록이 아니다.

`/Users/gnudas/wiki/concepts/awesome-ai-motion-video-reference.md`의 관련 후보만
선택하고, 한 사건의 주모션·보조모션·시선 목표를 명시한다. 큰 hit 뒤에는 읽기/연기
hold를 둔다. 효과 개수와 품질을 동일시하지 않는다. 사용자 no-text/차분한 톤은 우선한다.
발끝/머리/시선 anchor를 정렬하는 match cut은 실제 윤곽과 연속성을 보고 결정한다.

### 렌더와 검수

HyperFrames는 사례 구현이며 필수 설치 도구가 아니다. 현지에서 검증된 코드 렌더러로
BG/FG를 만들고, 필요한 합성 중간 소재를 만든 뒤 최종 CapCut 편집으로 전달한다.
오디오와 알파를 한 번에 해결하려 하지 말고 작은 샘플로 왕복·sync를 먼저 검증한다.
모션 코드·폰트·설정·EDL을 편집 미디어 옆에 보존해 수정 가능하게 한다.

검수는 (a) 프레임/알파/코덱 무결성, (b) 전체 재생과 청감, (c) 사용자 미감 승인을
분리한다. 기술 테스트 PASS를 창작 품질 PASS라고 보고하지 않는다. 빠른 플래시·RGB
분리·흔들림이 인물/문구를 가리면 강도를 낮추거나 제거한다.

## 첫 실전 검증

프로젝트의 승인 범위 안에서 짧은 구간으로 배경 유지 → 매팅 → 코드 합성 → CapCut
재생/export를 먼저 확인한다. 소요 시간·재생성 횟수·알파 결함·cue 오차·수정 시간을
기록한 뒤 확장한다. 여기의 지침 배포는 실제 Flow 생성/UI/합성 성능 검증과 별개다.
