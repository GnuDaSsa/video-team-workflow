# Seedance prompt compiler / same-owner review

한 작업자가 아래를 순차 확인한다. 별도 Creative 팀/critic agent를 만들지 않는다.
역할 이름이나 체크리스트 자체는 model-facing prompt로 보내지 않는다.
버전별 표현/모드는 선택한 prompting branch를 따른다.

## 저작 근거와 제출 전 독립 항목

모델/표시 라벨 정책의 원본은 runtime AGENTS §1.3이다. 자동 attestation은
형식·해시·길이·참조 계약 검사이며 모델 저작 또는 창작 품질 보증이 아니다.

새 reconciliation/승인용 JSON이나 프로젝트별 규칙 파일을 만들지 않는다.
기존 prompt package와 attestation을 기준으로 실제 작성 턴/모델 및 최종 문장을
대조한다. 근거는 기존 작업 이력 링크로 충분하며 라우팅 표나 자기 신고 모델
문자열로 대신하지 않는다. 모델 근거가 없으면 `HOLD_AUTHORSHIP_UNVERIFIED`,
문장이 바뀌면 기존 package를 새 revision으로 검토·attest한다.
이는 현재 작업자의 필수 검토 절차이며 자동 모델 검증기가 구현됐다고
설명하지 않는다. 기록을 추가하는 것 자체를 실행 수정이나 품질 개선으로
보고하지 않는다. 프로젝트 증거는 관측 사실만, 절차는 공통 원본에만 둔다.

- 숏마다 구도/크기, 등장 인원·화면 위치, 물리적 행동과 접촉, 시선/축,
  시작·종료 자세를 구체적으로 검토한다. ‘압박을 만든다’ 같은 감정 목표를
  행동으로 번역하지 않은 채 통과시키지 않는다.
- 네 숏이라는 숫자만으로 구성 PASS를 주지 않는다. 고정 카메라와 교차 편집,
  마지막 홀드와 번갈아 보여주기 등 상충 요구를 해소한다.
- human/drone 분리는 표현 대상을 나누는 것이지 이야기 원인을 삭제하는 것이
  아니다. 음악/편집에서 원인→반응이 연결되는 구간을 지정한다.
- 한 명 장면의 복수 인물 문구, 터널의 불필요한 네트 반응 등 템플릿 잔재를
  삭제한다. 금지어 반복을 긍정적인 연기·동작·공간 설계 대신 쓰지 않는다.
- 사용자 거부나 provider 정책 경고 후 자동 재생성하지 않는다. 정책 경고의
  원인은 관측 근거와 추정을 분리하고 정상적인 원본 내용 검토로 처리한다.

## Blender / 3D previs 조건부 검토

Blender/프리비즈 입력은 `blender-previs-prompting.md`의 source-role,
프록시 외형, 수정 패스 분리와 출력 판정 항목을 함께 검토한다.
이는 같은 owner의 시각 검토이며 자동 attestation PASS로 대체하지 않는다.

## 1. 장면 계약부터 확정

Package: 목적, 시작 상태 → 원인/접촉 → 반응 → 끝 상태, 음악 cue,
`render_scope` (`human_only`, `drone_only`, `mixed`, `environment_only`,
`object_only`), 등장 entity/수량, 지켜야 할 축/crop, 생성 시간 lock.
`render_scope`는 전역 세계관이 아니라 이번 출력에 실제 등장할 범위다.

먼저 사용자 원안에서 이 컷이 보여줘야 하는 **화면적 보상 한 문장**을 적고,
최종 프롬프트에 실제로 남았는지 확인한다. 사실·안전 사유로 조정했다면
원래 의도를 보존하는 대체 화면을 지정한다. `보류 메모 작성`은 기획 반영이 아니다.
복잡한 reference/물리/금지 조건을 붙인 뒤에도 첫 문단만 읽고 주인공의 행동과
카메라가 그려지지 않으면 다시 줄인다.

단일 숏이면 지속 가능한 행동을, multi-shot이면 필요한 2–4개의 서로 연결된 장면을
설계한다. 사용자가 명시한 15초/6×2.5초 등은 선택 버전의 explicit-shot 계약으로
보존하며 임의로 축소하지 않는다. 시간표는 프레임 정확도 보장이 아니라 연출 의도다.
정확한 beat sync/컷점은 출력 재생 검사와 편집에서 확정한다.

## 2. 레퍼런스는 기여 범위만

인접 deck 비교는 shared contract의 역할별 overlap 기준을 따른다. 검토 fixture:
- PASS: 서로 다른 장면 3장씩 + 동일한 승인 인물시트 2장. 공유 scene/action=0, 필수 identity=2.
- REPAIR: 서로 같은 장면 2장 + 동일한 승인 인물시트 2장. 공유 scene/action=2.
- REPAIR: 중복 장면을 identity로 이름만 변경. 승인 identity 자산 종류/등록 hash가 아니므로 예외 불가.
- BLOCKED: overlap을 줄이려고 등장 인물의 필수 시트를 제거. identity attachment gate 실패.

각 token마다 `가져올 것 / 가져오지 않을 것 / 적용할 scene`을 먼저 결정한다.
캐릭터 master는 얼굴·체형·의상, 환경은 공간, motion ref는 동선/리듬만 사용한다.
승인 identity/reference 연결은 생략하지 않되 관련 없는 참조는 추가하지 않는다.
첨부 순서가 사건 순서라는 암묵적 가정, 파일명, 업로드 지시는 prompt에서 제거한다.

## 3. 카메라와 물리는 결정문

- `3/4 추적 또는 정면 고정`은 미결정이다. 실제 하나를 선택한다.
- `측면 추적 후 인물이 멈추면 카메라도 감속해 고정`은 인과적 복합 연출이다.
  단순화를 위해 이를 금지하거나 사용자가 승인한 복합 액션을 지우지 않는다.
- 거리·각도·이동경로·시선/화면방향·끝 구도를 명시한다. 형용사로 대신하지 않는다.
- 사람: 발 접지/체중 이동/행동 뒤 지연되는 의복 등 보이는 층만.
- 드론: 본체 관성/뱅크/안정화/환경 parallax 등 실제 물체에 맞는 층만.
- 2D: 승인된 선/색면/음영법을 유지. 실사 피부/모공/불필요한 grain을 주입하지 않는다.
- 매 숏에 머리카락·소매·입자 2–4개를 기계적으로 붙이지 않는다.

## 4. 모델 문장으로 컴파일

화면에 보이는 전제 → 필요한 token 결속 → 숏별 행동/카메라/시간 진행 →
끝 구도와 소리. 이미 결속된 전역 identity 설명을 매 scene 반복하지 않는다.
선택된 언어 계약으로 작성한다(기본 한국어, 명시적 사용자 영어 요청은 현행
hash-bound language override). `을(를)` 같은 template 찌꺼기는 실제 문장으로 치환한다.
긴 프롬프트라는 이유만으로 잘라내지 않는다. 제거 대상은 중복/모순/무관한
통제 문구이며, 고유한 인과·identity·공간·사용자 지정 복합 연출은 보존한다.
제약은 관련 위험에 한정한다. 과거 프로젝트 금지 목록을 전 작품에 붙이지 않는다.

## 5. 반례 검토 + 현행 attestation

| 검토 질문 | FAIL 예 |
|---|---|
| 이번 출력에 없는 entity가 행동하는가? | drone_only에 소매/머리카락 반응 |
| 제외하려다 오히려 등장시켰는가? | human_only에 “드론은 공중에만 머문다” |
| 카메라를 결정했는가? | 추적 또는 정면 고정 |
| prompt와 package가 같은 plan인가? | 참조/scene/시간/끝 상태 불일치 |
| 실행 메모가 누출됐는가? | 입력 모드:, 업로드 경로, 파일명 |
| 읽어보면 행동이 실제 수행 가능한가? | 접촉 전 반응, 순간이동, 동시 다발 사건 |

`shot_semantics.py`는 위에서 관찰된 좁은 회귀만 검출한다. PASS가 전반적 의미
정합성이나 영상 품질을 보증하지 않는다. 새 오류는 재현 가능한 good/bad fixture를
만든 뒤 검출기로 승격한다. 기존 pack을 자동 수정하거나 자동 재승인하지 않는다.

## 6. 수정과 품질 측정

실패는 `identity / reference_scope / camera / physics / timing / texture /
operator / provider`로 분류하고, 근거 있는 원인 한 가지를 교정해 revision을 남긴다.
문장 문제면 해당 문장만, 입력 이미지·프록시·공간 설계 문제면 그 입력을 바꾼다.
원인이 reference인데 문장만 바꾸는 것은 유효한 단일 변수 실험이 아니다.
동일 조건의 작은 A/B 이후 첫 생성 승인율, 재시도 수, 사용 가능 초/생성 초,
identity FAIL, 실제 채택 cut 수를 기록한다. 관찰치 없이 “프롬프트 개선 성공”이라
하지 않는다. QC는 정지 화면뿐 아니라 접촉 전후와 끝 handle을 재생 검사한다.

### 반복 실패: 입력 → 공간 → 동작 → 효과 순서로 진단

같은 실패가 2회 이어지면 같은 참조·구도를 유지한 채 `더 빠르게`, `공중에서만`,
`절대 금지`를 늘리는 재시도를 중단한다. 현재 실패 범위만 기존 QC report와
다음 prompt revision에 연결한다. 다른 독립 장면 제작까지 멈추라는 뜻은 아니다.

1. **관측과 추정 분리.** 바닥 근처라는 사실만으로 “굴러다닌다”라고 판정하지
   않는다. 바닥 접촉, 몸체 회전축, 분리된 그림자, 실제 공극을 연속 프레임에서
   확인한다. 낮은 호버링과 접지 구름은 다른 결함이며 수정도 다르다.
2. **참조 우선순위 점검.** 정체성 시트의 회색 바닥·접지 그림자·전시 포즈가
   장면으로 전이됐는지 본다. 각 참조에 가져올 형상/색/의상과 적용 숏을 결속하고,
   배경/포즈 기여는 환경/행동 참조와 분리한다. 같은 입력이 계속 새면 승인
   identity를 보존하는 최소 crop/재구성 또는 높이가 읽히는 환경 참조를 준비해
   QC한다. 단순 negative 추가, 필수 identity 제거, 첨부 안 한 참조 사용 주장 금지.
3. **공간 증거 설계.** 고도는 말보다 상부 그물/관중석과 기체의 상대 높이,
   아래로 떨어진 그림자, 전후경 parallax로 읽히게 한다. 카메라가 위를 본다고
   기체가 높이 난 것은 아니다. 넓은 구도에서 필요한 구조물은 같은 경기장의
   공간 계약을 유지하고, 근경용 빈 배경을 경기장 전체 기준으로 쓰지 않는다.
4. **물체와 조종자 분리.** 사람 이름으로 기체 동선을 지시하지 않는다. 화면에
   있는 기체의 고유 형상/색 + token으로 식별하고, 조종자 행동은 별도 숏/주체로
   적는다. 종목명만으로 규칙을 추론시키지 말고 목표물 형태, 고정 위치, 득점
   조건을 관측 가능한 사건으로 쓴다. 사용자가 허용한 비현실적 능력은 보존한다.
5. **접촉과 회피의 인과.** 시작 위치 → 접근/뱅크 → 실제 접촉 또는 명확한
   여유 간격 → 양쪽 반동/관성 → 자세 회복과 이탈을 잇는다. 상대가 이유 없이
   멈추거나, 본체가 겹쳐 통과하거나, 카메라 회전만으로 회피한 척하면 HOLD다.
   모든 기체에 같은 움직임을 붙이지 말고 공격·차단·미끼·회복 역할을 나눈다.
6. **기본 사건이 읽힌 뒤 표현 강화.** 번개 잔상은 이미 지난 궤적을 짧게 따라가고,
   나선/검은 배경/분할 화면은 접촉·회피·도착의 연결을 가리지 않는 순간에 둔다.
   휘광으로 형태나 득점 증거를 숨기지 않는다. 강한 소년 스포츠 애니 액션을
   포기하라는 뜻이 아니라 속도 변화와 명료한 원인/반응 위에 얹는 것이다.

### 입체 통과·득점 검토 (해당 장면에만)

한 프레임에서 기체가 링 안에 겹쳐 보이는 것은 **목표 평면 통과의 증거가 아니다**.
진입 전 접근 쪽 → 고정된 목표 평면에서의 일관된 가림 관계 → 반대쪽으로
완전히 이탈한 실루엣이 연속적으로 읽혀야 한다. 평면 양쪽 테두리가 모두 기체를
가리는 횡이동은 단순히 링 뒤를 지나간 것일 수도 있으므로 재생·깊이 단서 없이
득점 PASS하지 않는다. 안전한 3/4 축, 고정 링 두께/축, 앞뒤 parallax 등 현재
구도에 맞는 증거를 설계한다. 특정 가림 순서 하나를 모든 카메라에 강제하지 않는다.

닫힌 목표물의 형태·개수·위치는 접근부터 이탈까지 유지한다. 한 번 득점하는
숏이면 기체가 목표물 주변을 반복 선회하거나 재진입하지 않게 끝 상태를 정한다.
점수 변화/효과음은 확인 가능한 완전 이탈 뒤에만 둔다. 결과에서 증거가 부족하면
`HOLD_SPATIAL_EVENT_UNPROVEN`; 편집 insert 후보와 경기 결과 증명을 분리한다.

수정안은 기존 package에 `관측한 실패 / 원인 가설 / 바꾼 입력 또는 문장 /
출력에서 확인할 구간·증거`를 남기고 다시 attest한다. 이 체크리스트가 통과해도
실제 새 영상이 개선됐다는 주장은 새 출력 QC 뒤에만 한다.

### 교정 예 — drone_only, 15초 단일 숏 (설명용)

잘못: `3/4 추적 또는 정면 고정. 소매와 머리카락이 바람에 반응한다.`
교정: `@Image1의 드론 본체 형상과 표면 재질을 유지한다. @Image2는 도시의
공간 구조와 낮은 해의 방향만 제공한다. 카메라는 드론의 왼쪽 뒤 3/4에서 같은
속도로 추적한다. 첫 4초 직진 후 완만하게 우측으로 뱅크하고, 본체가 수평으로
